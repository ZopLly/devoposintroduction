1. Сделал две разных ветки для безопасных изменений проекта. 
2. Запуллил и сделал мердж изменения в главную ветку с веткой плна.
3. Скачал докер, докер композе, поднял локально на портах 8080 и порту 80 нджинкс. Два порта нужны так как контейнер слушает внутри своего сетевого окружения один порт, и снаружи другой. Заходит на адрес 127.0.0.1 и выдает начальный экран нджинкс  
докер файл находится в репо с проектом добавил фай index.html с первичным видом окружения, запушил в репозиторий на гитхаб для дальнейшей работы
Создан файл Dockefile для развертывания сайта на др устройствах 
4. В репозитории создал воркфлоу файл. В нем реализовал CI/CD на базе GitHub Actions. Воркфлоу настроил так, чтобы он запускался от любого пуша в репозитории. Создал job: ci, который отвечает за автоматическую проверку проекта: собирает докер образ из репозитория, запускает его и сайт, присылает сайту http запрос (если сайт отвечает, то тест пройден успешно), после проверки контейнер удаляется.
5. Создал job: cd, который отвечает за публикацию готового докер образа. Настроил его так, чтобы он запускался от пуша в main и после успешной проверки (ci). Для хранение докер образа был выбран GHCR. Перед публикацией было сделано: авторизация с использованием встроенного токена и добавлением разрешения воркфлоу для публикации в GHCR, сборка образа. Дальше сама публикация на GHCR. 
6. Добавил деплой в воркфлоу, который работает после успешного выполнения ci, cd. Для подключения GitHub actions и сервера были созданы секреты в GitHub secrets (host, user, key). Написал команды для подключения к серверу. После написал скрипт, которые выполняются на самом сервере: создания отдельной папки, создание compose.yml с нашим докер образом из GitHub, получения новой версии образа и запуск его.
