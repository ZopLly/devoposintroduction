1. Сделал две разных ветки для безопасных изменений проекта. 
2. Запуллил и сделал мердж изменения в главную ветку с веткой плна.
3. Скачал докер, докер композе, поднял локально на портах 8080 и порту 80 нджинкс. Два порта нужны так как контейнер слушает внутри своего сетевого окружения один порт, и снаружи другой. Заходит на адрес 127.0.0.1 и выдает начальный экран нджинкс  
докер файл находится в репо с проектом добавил фай index.html с первичным видом окружения, запушил в репозиторий на гитхаб для дальнейшей работы
Создан файл Dockefile для развертывания сайта на др устройствах 
4. В репозитории создал воркфлоу файл. В нем реализовал CI/CD на базе GitHub Actions. Воркфлоу настроил так, чтобы он запускался от любого пуша в репозитории. Создал job: ci, который отвечает за автоматическую проверку проекта: собирает докер образ из репозитория, запускает его и сайт, присылает сайту http запрос (если сайт отвечает, то тест пройден успешно), после проверки контейнер удаляется.
5. Создал job: cd, который отвечает за публикацию готового докер образа. Настроил его так, чтобы он запускался от пуша в main и после успешной проверки (ci). Для хранение докер образа был выбран GHCR. Перед публикацией было сделано: авторизация с использованием встроенного токена и добавлением разрешения воркфлоу для публикации в GHCR, сборка образа. Дальше сама публикация на GHCR. 
6. Добавил деплой в воркфлоу, который работает после успешного выполнения ci, cd. Для подключения GitHub actions и сервера были созданы секреты в GitHub secrets (host, user, key). Написал команды для подключения к серверу. После написал скрипт, которые выполняются на самом сервере: создания отдельной папки, создание compose.yml с нашим докер образом из GitHub, получения новой версии образа и запуск его. 
7. Добавил в compose.yml Prometheus и Grafana. Для Prometheus настроил сбор собственных метрик каждые 15 секунд. Для Grafana настроил автоматическое подключение к Prometheus как к источнику данных. Создал именованные volumes для сохранения данных после удаления и пересоздания контейнеров.

8. Ограничил доступ к сервисам: сайт доступен на 127.0.0.1:8080, Prometheus — на 127.0.0.1:9090, Grafana — на 127.0.0.1:3000. Эти порты не опубликованы на внешних сетевых интерфейсах сервера.

9. Проверил логи GitHub Actions. Сборка, HTTP-проверка сайта и публикация образа в GHCR прошли успешно. Деплой через SSH завершился ошибкой: переданное значение ключа не было распознано как приватный SSH-ключ. Эта ошибка не отменила публикацию образа.

10. Изменил схему развёртывания: вместо VPS выбрал домашний сервер с CachyOS и Docker Compose 5.6.0. Старый job deploy в GitHub Actions отключил. Проверку и публикацию образа оставил автоматическими, а развёртывание решил запускать вручную одной командой с ноутбука.

11. Настроил Tailscale на ноутбуке и домашнем сервере для приватного удалённого подключения. Проверил SSH-доступ к серверу. Для этого подключения не потребовался проброс SSH-порта на роутере.

12. Склонировал главную ветку репозитория на сервер в /home/andrew/devops-deployment-dashboard. Compose использует готовый образ сайта из GHCR, поэтому собирать сайт непосредственно на сервере не требуется.

13. Создал на сервере скрипт /usr/local/bin/deploy-dashboard. Скрипт скачивает образы через docker compose pull, запускает весь стек через docker compose up -d и проверяет HTTP-ответ сайта и наличие названия проекта в HTML. Добавил повторные попытки проверки и блокировку одновременных запусков. При неуспехе скрипт выводит логи сайта и завершается с ошибкой.

14. На ноутбуке создал функцию deploy. Она подключается к серверу по SSH через Tailscale и запускает скрипт с sudo. Таким образом, одной командой можно запустить или обновить сайт, Prometheus и Grafana.

15. Настроил SSH-туннель для просмотра сервисов с ноутбука. Локальный порт 18080 направляется на порт 8080 домашнего сервера, а порт 13000 — на серверный порт 3000. Сайт открывается на localhost:18080, Grafana — на localhost:13000. Эти адреса доступны на моём ноутбуке, а не публично в интернете.

16. Провёл тест полного развёртывания: остановил проект через docker compose down, затем запустил deploy с ноутбука. Скрипт скачал образы, создал сеть, запустил три контейнера и успешно проверил сайт. Данные мониторинга сохранились, поскольку volumes не удалялись.
