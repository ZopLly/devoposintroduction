# DevOps Deployment Dashboard

Учебный проект по методологии DevOps.

Цель: автоматическая проверка, сборка и развёртывание веб-приложения
с помощью GitHub Actions, Docker и Nginx.


## План 

1. Git: ветки и Pull Request.
2. GitHub Actions: автоматическая проверка проекта.
3. Docker: сборка образа и запуск контейнера.
4. Автоматическое развёртывание на учебном сервере.
5. Nginx и HTTPS.
6. Мониторинг через Prometheus и Grafana.

## Текущее состояние

Git/PR, сборка Docker-образа и HTTP-проверка в GitHub Actions реализованы.
При push в main образ публикуется в GHCR с тегами `latest` и `sha-<полный SHA>`.
Развёртывание запускается вручную; автоматического deploy после push нет.
Nginx раздаёт сайт по HTTP. HTTPS пока не настроен.
Prometheus собирает собственные метрики; Grafana автоматически подключается к нему.
Проверки доступности сайта и готового dashboard мониторинга пока нет.

## Ручное развёртывание конкретной версии

Требования на учебном сервере: Bash, Git, curl, flock (util-linux), Docker Engine
и Docker Compose с поддержкой `configs.content`. Пользователь должен иметь доступ
к Docker. Сервисы слушают только loopback: сайт 8080, Prometheus 9090, Grafana 3000.
Для удалённого доступа используется существующее SSH/Tailscale-подключение.

После слияния PR дождитесь успешного job `cd` в Actions: образ с SHA **коммита
в main** должен быть опубликован. SHA ветки до merge может отличаться.
На сервере, в клоне репозитория:

```bash
git switch main
git pull --ff-only
bash scripts/deploy-dashboard "$(git rev-parse HEAD)"
```

При недостаточных правах на Docker последнюю команду запускайте через `sudo bash`.
Если пакет GHCR приватный, предварительно выполните `docker login ghcr.io`
под той учётной записью ОС, которая будет запускать Docker.

Скрипт берёт Compose из своего checkout, загружает только образ сайта нужного SHA,
запускает весь стек и проверяет `/build-sha.txt` и название проекта в HTML.
Повторный запуск с тем же SHA допустим. Одновременный deploy из одного checkout
блокируется. Нельзя использовать разные checkout для параллельного управления
одним стеком. При ошибке выводятся состояние контейнеров и логи web; автоматического
отката нет, после неудачной проверки новая версия может остаться запущенной.

Можно явно передать SHA предыдущего опубликованного main-коммита для возврата
версии сайта. Это меняет образ, но не откатывает Compose-конфигурацию.
Скрипт не делает `git pull`: изменения Compose нужно получать отдельно.
Не запускайте голый `docker compose up -d` после deploy по SHA: без `WEB_IMAGE`
Compose использует `latest`. Для операций над выбранной версией задавайте
`WEB_IMAGE=ghcr.io/zoplly/devoposintroduction:sha-<SHA>` или повторяйте скрипт.

Существующие `/usr/local/bin/deploy-dashboard` и функция на ноутбуке автоматически
не заменяются. Для запуска с ноутбука вызовите этот скрипт в серверном checkout
через уже настроенный SSH. Адрес сервера и SSH-ключи в репозиторий не добавляются.

## Проверки перед защитой

```bash
bash -n scripts/deploy-dashboard
python3 -m unittest discover -s tests -v
docker compose config -q
```

В CI также собирается и запускается настоящий образ, проверяются HTML и SHA сборки.
Python-тесты запускают настоящий HTTP-сервер и curl, но подменяют Docker:
они проверяют логику deploy, а не работоспособность Docker Engine.

На учебном сервере проверьте переход с предыдущей версии на новую:

1. Измените страницу через PR и дождитесь публикации образа main-коммита.
2. Обновите checkout и выполните deploy с SHA этого коммита.
3. Сверьте `curl -fsS http://127.0.0.1:8080/build-sha.txt` с запрошенным SHA,
   проверьте видимую версию страницы через существующий SSH-туннель.
4. Повторите deploy того же SHA; проверьте три контейнера через `docker compose ps`.
5. Убедитесь, что Grafana сохранила данные. Не удаляйте volumes (`down -v`).

Сборка без `--build-arg BUILD_SHA=...` получает маркер `local` и не подходит
для проверки deploy по SHA. `v1.2` на странице — версия интерфейса,
а `/build-sha.txt` — точная идентичность сборки.
